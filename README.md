
**ЦРМ — Цифровое рабочее место** — это единая точка управления мероприятиями и связанными сделками в Bitrix24. Приложение собирает данные CRM в понятный операционный отчёт и даёт инструменты для ежедневной работы менеджера: от контроля воронки до массового создания сделок и выгрузки в Excel.

**Что вы получаете**

- **Сводная панель** — собранная выручка, план, количество мероприятий и сделок за выбранный период.
- **Активность по мероприятиям** — таблица с фильтрами по группам, ответственным и датам; быстрый переход к карточке мероприятия в CRM.
- **Панель сделок мероприятия** — стадии «Потенциал», «Договоренности», «Передано», «Отказ»; контроль обязательных полей, статуса участия и доверенного лица.
- **Генератор сделок** — точечное и массовое создание сделок по мероприятию.
- **Рассылки и работа с аудиторией** — приветственные рассылки и сегментация контактов.
- **Чек-листы мероприятий** — прогресс подготовки прямо в интерфейсе отчёта.
- **Экспорт** — Excel по стадиям воронки (как в ODK), выгрузка научной программы, сохранение отчёта в виде снимка экрана.
- **Навигация по отчётам** — быстрый доступ к смежным аналитическим приложениям портала.

**Для кого**

- команды продаж и спонсорства мероприятий;
- event-менеджеры и руководители направлений;
- компании, где воронка сделок привязана к календарю мероприятий и требует жёсткого контроля полей на каждой стадии.

**Почему это удобно**

Вместо ручной сводки в таблицах и переключения между десятками списков CRM — один экран с актуальными цифрами и действиями. Менеджер видит, где «проседает» мероприятие, какие сделки не доведены до нужной стадии, и может сразу создать сделку, отправить рассылку или выгрузить отчёт для руководства.

**Технологии:** Vue 3, Vite, Vuetify, Bitrix24 REST / JS SDK. Работает как локальное приложение (placement) внутри портала Bitrix24.

- Node.js 20+
- Размещение как локальное приложение Bitrix24 (placement) или доступ к REST webhook

## Установка и запуск

```bash
npm install
npm run dev
```

Dev-сервер: `https://127.0.0.1:5173` (см. `vite.config.ts`).

Сборка:

```bash
npm run build
```

Перед сборкой выполняется `vue-tsc --noEmit`.

## Структура `src/`

```
src/
  domain/           # Чистая доменная логика (стадии, поля, viewport)
  functions/        # API/helpers (callApi, dateFilter, exportEventReport, …)
  pages/            # Главный экран отчёта (Home.vue), callApi
  components/       # UI: EventDealsDialog, DealGenerator, формы, графики
  stores/           # Pinia stores
  composables/      # Vue composables
  tests/            # Unit-тесты Vitest
```

## Стадии и обязательные поля

Правила заданы явно в `src/domain/dealStages.ts` (не card-config Bitrix):

| Переход / стадия | Обязательные поля |
|------------------|-------------------|
| Потенциал холодный → Договоренности тёплые | Предварительная сумма (`UF_CRM_1742971372921`) |
| Договоренности холодные → Передано | Статус участия + кв.м |
| Передано | Финальная сумма + доверенное лицо |

Отказы и служебные поля (комментарии, внебюджет, коммерция и т.д.) в обязательные не входят.

## Экспорт Excel

`src/functions/exportEventReport.ts` — группировка как в ODK: четыре блока стадий, колонка «Доверенное лицо», пустые группы тоже выводятся.

## Тесты

Unit-тесты (без UI Bitrix):

```bash
npm run test
```

Покрывают:

- `dealStages` — карта обязательных полей
- `dealFields` — `normalizeIdList`, empty/serialize
- `exportEventReport` — группировка сделок
- `dialogViewport` — ограничение высоты iframe
- `dateFilter` — форматирование диапазонов (unit)

Интеграционные тесты с webhook помечены `describe.skip` и включаются вручную при наличии доступа к Bitrix.

## Встраивание в Bitrix24

- Основной путь: `BX24.callMethod` / `BX24.openPath` / `BX24.resizeWindow`
- Fallback: REST webhook (`src/functions/bitrixWebhook.ts`, `src/pages/callApi.ts`)
- Типы `BX24` объявлены в `src/env.d.ts`

## TypeScript

- `strict: true` в `tsconfig.json`
- Для постепенной миграции крупных SFC: `noImplicitAny: false`, `strictNullChecks: false`, `vueCompilerOptions.strictTemplates: false`
- Vue SFC используют `<script setup lang="ts">` / `<script lang="ts">` (в крупных legacy-компонентах временно `// @ts-nocheck`)
- Доменная логика вынесена в `src/domain/*` и покрыта unit-тестами без `@ts-nocheck`
